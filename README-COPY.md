# nixos-rice — copy & apply

Everything in this folder is written for the live config at `/etc/nixos`
(user `veer`, host `nixos`, Hyprland 0.55.4, Home Manager release-26.05).

## Apply

```bash
cd ~/Public/nixos-rice
./install.sh              # backup -> copy -> dry build -> switch
./install.sh --no-switch  # stop after the dry build
```

Manual equivalent: back up `/etc/nixos`, copy the files listed in
`MANIFEST-delete.txt` (and delete the listed `.nix` files), then
`sudo nixos-rebuild switch --flake /etc/nixos#nixos`.

Afterwards: **log out and back in** (shell session, plugin binds, SDDM cursor),
reboot once for the plymouth splash.

## matugen (dynamic theming)

- Config + templates: generated by `hm-modules/matugen.nix`
  (`~/.config/matugen/config.toml`, `~/.config/matugen/templates/`).
- Outputs: `hyprland-colors.lua`, `kitty-colors.conf`, `fuzzel-colors.ini`,
  `~/.config/btop/themes/matugen.theme`, `~/.config/zathura/zathurarc`,
  plus wallpaper-synced `~/.config/starship.toml`,
  `~/.config/hypr/hyprlock.conf`, `~/.config/matugen/qt6ct-colors.conf`
  (Qt6 apps pick it up via `QT_QPA_PLATFORMTHEME=qt6ct`, `hm-modules/qt6ct.nix`).
- Re-theme anytime: `SUPER W` (wallpaper picker — also sets
  `caelestia wallpaper -f` and re-runs matugen) or `SUPER SHIFT T`
  (theme switcher — scheme family, flavour, dark/light, variant, random
  scheme/wallpaper without changing the wallpaper).
- The chosen matugen flavour/mode is kept in `~/.cache/matugen-state`, so
  every re-theme (keybind, wallpaper change, first-boot bootstrap) reuses it.
  The Caelestia scheme (`caelestia scheme set …`) and the matugen `-t/-m`
  flags are both managed by the theme switcher — keep them in sync by using
  it instead of calling `caelestia scheme set` by hand.
- On first switch, `home.activation.matugenBootstrap` creates all outputs
  from your current wallpaper (only if missing), so no `include` ever
  points at a missing file. `install.sh` re-runs matugen after the switch.
- **Starship**: the whole `~/.config/starship.toml` is generated
  (`hm-modules/zsh.nix` no longer ships a static copy — starship has no
  `palettes_dir`, the palette must live in the same file). Edit the template
  in `hm-modules/matugen.nix` → `xdg.configFile."matugen/templates/starship.toml"`.
- **hyprlock**: the static `hm-modules/hyprlock.nix` is dropped; hyprlock now
  reads the matugen-generated `~/.config/hypr/hyprlock.conf`.

## Notes / gotchas

- **100% Nix**: every Lua file, shell script, and matugen template is inline
  `.text` inside `hm-modules/*.nix` — that is the only place to edit them
  (no loose `.lua`/`.sh` files in the repo).
- Four imported modules are **not** part of this folder and stay as they are
  on your machine: `hm-modules/{secrets,git,gtk,default-apps}.nix`
  (secrets stay out of the rice; git/gtk/defaults were already fine).
- Paths are hardcoded to `/home/veer` in a few places (look.lua, fuzzel include,
  kitty include) — change them if the username ever changes.
- New flake input: `caelestia-shell` (no follows; it pins its own nixpkgs for
  the shell package). First build downloads quickshell/Qt — expect a long build.
- Hyprland looks for `hypr/hyprland.lua` first; the old managed
  `hypr/hyprland.conf` is removed by Home Manager on switch.
- Launcher-set wallpapers via `>wallpaper` inside Caelestia do **not** run
  matugen (use `SUPER W` for full re-theming).
- The scheme auto-set at login (`dynamic`) only runs once — afterwards your
  last chosen scheme survives logins (stored in
  `~/.local/state/caelestia/scheme.json`).
- btop is switched to `color_theme = "matugen"` by install.sh; revert in
  btop.conf if you want the old theme.
- Old configs are moved, not deleted: `~/.config/rice-removed-<timestamp>/`.
